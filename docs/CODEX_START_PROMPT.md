# Codex task — Season of Broken Hearts: bootstrap and first vertical slice

**Repo:** https://github.com/m-amirov/Season-of-Broken-Hearts  
**Game:** «Сезон разбитых сердец» / Season of Broken Hearts  
**Authoritative starting concept:** `docs/CONCEPT.md`  
**Project local bootstrap guide:** `docs/BOOTSTRAP.md`

## Цель

Превратить новый репозиторий с концепцией в корректно инициализированный и локально запускаемый проект романтической новеллы для Яндекс Игр. Сначала безопасно установить Starter Kit и CEOS, затем создать narrative bible, формальную схему сюжета и минимальный вертикальный срез первого эпизода. Не заявлять о готовности всей игры или релиза.

## Обязательные действия и ограничения

1. **Discovery first.** Самостоятельно исследуй репозиторий, текущую ветку, worktree, локальные исходники, установленные версии CEOS, node/npm, Codex hooks, существующие шаблоны и команды. Не предполагай заранее файловую структуру, путь рабочей копии, наличие арта или какие-либо уже пройденные проверки. Не уничтожай незакоммиченные изменения. Если рабочего checkout нет, клонируй указанное repo.
2. **Starter Kit first.** Используй официальный `m-amirov/starter-kit-yandex-games`, текущая на 2026-10-13 версия `0.5.12`, commit `a9acd7e8ab344af1c13e2ecb0807678cf52edf37` (сверь фактическую актуальную версию). Из отдельного checkout выполни `init-project.mjs` с `--profile new-project` и обязательным `--dry-run` перед записью. Разреши конфликты без потери концепции. Не копируй вручную весь kit и не применяй mature-profile.
3. **CEOS.** Используй официальный `m-amirov/codex-engineering-system`, проверенная версия `0.5.12`, commit `8276dac7d310797dacdba30c697834a03e5417ea`. Проверь `ceos version`. При необходимости обнови глобальную Windows-установку штатным `scripts/install-global.ps1 -Web auto` из отдельного checkout. Выполни `ceos adopt --project ... --dry-run --json`, затем `ceos adopt --project ... --profile yandex-games`. Запиши реальные результаты `ceos version`, `global-status`, `capabilities` и Web preflight. После глобальных изменений потребуется новая сессия Codex: не притворяйся, что текущая уже перезапущена.
4. **Ownership.** Не затирай Starter Kit managed-файлы и существующие правила проекта. Концепция `docs/CONCEPT.md` — исходный канон. Конфликтующие решения фиксируй явно в отчёте. Project-owned спецификацию и правила адаптируй к новелле после init.
5. **Narrative-game.** По настоящему README/`docs/NARRATIVE_GAME_PROFILE.md` Starter Kit определи и подключи optional profile `narrative-game`. Создай реальную схему диалогов/маршрутов, экспорт её состояний и sample saves из работающего runtime, а не фальшивую тестовую модель. Подключи ledger сюжетных обещаний. Пока настоящих входных данных нет, честно фиксируй `NOT_READY` вместо ложного PASS.

## Нарративный дизайн

Из `docs/CONCEPT.md` разработай project-owned файлы канона:
- `narrative/NARRATIVE_BIBLE.md`: биографии/характеры, 8-летняя хронология Ники и Лео, мотивы и секреты Маттео, Лео, Элио, Бьянки, временная шкала лета и финансовая причинность отеля.
- `narrative/ROUTE_MAP.md` или эквивалент: последовательность 10 эпизодов, маршрутные состояния, route-lock в эпизоде 6, независимая ветка, семь финалов отношений и три исхода отеля, с определёнными условиями без недостижимых/битых путей.
- `narrative/STYLE_GUIDE.md`: русская литературная стилистика, естественные разговорные реплики, отсутствие «нейрослопа», отдельная манера речи каждого героя, баланс страсти/эмпатии/конфликтов, осмысленные cliffhangers.
- `narrative/STORY_PROMISES.md` и машиночитаемый ledger (когда появится source graph) — setup/payoff, особенно прошлое Лео, документы Маттео, решение Элио об отъезде и исход сделки.
- `narrative/EPISODE_OUTLINE.md`: детальный scene-by-scene план 10 эпизодов **без полного написания всех эпизодов**. Сцены должны иметь цель, конфликт, персонажей, локацию, условие входа/выхода, важные выборы.
  
Не меняй принципиальные элементы исходной концепции без обоснованного изменения самой концепции. В частности, Ника посещала регион восемь лет назад, но до текущего сезона в отеле не работала; фиктивные отношения необязательны и не влияют на сохранение рабочего места.

## Первый работающий срез

- Создай рабочую архитектуру браузерной интерактивной новеллы поверх Starter Kit, исходя из реально предоставленных шаблонов (не из догадок). Минимальная вертикальная история: эпизод 1, его реальные развилки, знакомство с тремя интересами, кульминационная встреча с Лео, плавный переход к следующему эпизоду.
- Повествовательный движок: данные сцен и реплик отдельно от rendering/UI; уникальные IDs, валидные переходы, predicate guards/effects, детерминированное состояние, версионированные сохранения, восстановление после reload, корректное New Game и Back (откат на предыдущий диалог/выбор без порчи состояния).
- RU/EN с раздельными локализованными строками, переключение языка не сбрасывает сюжет/выборы. Английская версия первого среза должна быть естественной, не машинно-калькированной.
- UX: портретный приоритет, адаптация 360×640 и 390×844, безопасная текстовая область, крупные touch-target, защита от автопрокликивания после выбора, нормальная скорость текста. Не добавляй обязательную landscape-версию только ради формального чек-листа, соблюдай действующие требования платформы.
- Art: сначала asset inventory и art/style bible. Предпочитай цельные CG вместо наложения разрозненных спрайтов; preload/crossfade. Если настоящей image-generation capability нет, используй явно помеченные временные placeholders, сохрани `BLOCKED_ART_PRODUCTION` и не утверждай art PASS. Не массово генерируй графику для сезона до concept proof.
- Для первой новеллы НЕ вводить внутреннюю валюту, premium choices, rewarded unlocks или IAP. Яндекс SDK и политика локализаций/отправки событий — только согласно действительно текущим Starter Kit контрактам.
- Не добавлять тяжелые зависимости и большой рефакторинг без подтверждённой необходимости.

## Проверки и evidence

Проверь именно реальный новый проект. Реальные имена npm scripts бери из `package.json`, не придумывай.
- Starter Kit: init report, status, self-tests, manifest; конфликты 0 либо объяснены и устранены.
- CEOS: `version`, `global-status`, `adopt`, `capabilities`; routing/browser/Web High отдельно со своими доказательствами, а не только health READY.
- Narrative: ID и граф переходов, достижимость, route-lock, state guards, сериализация, New Game/Back/reload, миграции версий, отсутствие false-pass в optional profile.
- Runtime: локальный запуск, реальный browser smoke, console/network errors, touch взаимодействия и читабельность текста на 360×640 и 390×844. Создай скриншоты и проверь на них текст и изображения; CSS-only/DOM-only PASS не считается полноценным visual acceptance.
- Сюжет: независимый reader-comprehension/continuity review на EP1, факты/хронология/места, мотивы, tone-of-voice; поздние сюжетные обещания учитывать как планируемые, не помечать как уже выполненные.
- SDK/localization/build: выполнить фактические доступные валидаторы; никаких заявлений о production Yandex PASS, Draft PASS, art PASS, Web High PASS без соответствующего evidence.
- Гейты релиза: нельзя объявлять игру/релиз готовым без полноценного route+save E2E, art acceptance, SDK checks, media compliance, Web High по принятому host-observed стандарту с реальными ответами, Draft/external runtime QA и финальной сборки с правильной структурой.

## Правила исполнения

Работай последовательно: bootstrap → evidence → narrative bible/route map → EP1 vertical slice → tests → audit → коммит. Не запускать массовое сочинение всех 10 эпизодов, не выполнять бессмысленные циклы косметических художественных исправлений. Правь root cause, добавляй regression tests. Не расходуй GitHub Actions на Linux QA при наличии локальной возможности. Если доступен push и рабочая ветка/права позволяют, закоммить и отправь изменения в `main`; не force-push. Не помечай неполные этапы как PASS.

## Acceptance criteria этапа

1. Репозиторий содержит корректный Starter Kit new-project baseline и CEOS project adoption (оба подтверждены статусом/артефактами, не только наличием папок).
2. Есть narrative bible, маршрутная схема, style guide, эпизодный план и ledger.
3. EP1 реально запускается; доступны RU и EN, диалоги, выборы, Back и сохранения с минимальной регрессией.
4. В автоматической проверке покрыты хотя бы основные переходы EP1, reload и возврат; в мобильных проверках нет самопроизвольного выбора.
5. Все пройденные проверки имеют явные команды/лог/артефакты. Блокеры отдельно перечислены.
6. Изменения закоммичены и запушены, сохранены commit SHA и clean/dirty status. Если установка глобальной CEOS потребовала перезапуска — это явно отмечено как pending, а не «готово».

**Финальный формат отчёта:** исходный/финальный HEAD; Starter Kit version/status; CEOS version/adoption/capabilities; изменения по файлам; состояние EP1; реальные команды и результаты; подтверждённые и неподтверждённые gates; blockers; точный следующий шаг.
